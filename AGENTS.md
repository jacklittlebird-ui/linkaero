# Architecture rules
- AppLayout's workspace owns desktop intrinsic content width so headers, statistics and wide tables scroll together; mobile keeps viewport width and local table scrolling to prevent clipping.
- Cash-box options are configured records linked to exact posting accounts in the chart, never chart IDs passed as cash-box IDs; this preserves voucher foreign keys and ledger linkage.
- Treasury entry uses paginated posting-account loading and normalized Arabic/code search; this prevents API row caps and spelling variants hiding chart accounts.
- Treasury voucher numbers are reserved atomically for the authenticated user when opening the form and consumed by the insert trigger, with insert-time numbering for legacy clients; CBE side rates are enforced server-side without altering unchanged historical vouchers.
- Airline-specific Air France staff fields and print rows share a single definition in the security task-sheet module; this prevents arrival/departure labels and saved keys drifting between the form and PDF.
- Store airline-specific operational fields in existing task_sheet_data JSON, retaining flight_schedules as the flight identity source; this avoids schema changes and preserves the frozen SSoT architecture.
- Keep the Vercel asset proxy rewrite before the SPA fallback so uploaded report logos and print-image requests resolve to images rather than index.html on self-hosted deployments.- Treasury vouchers require their cash box/bank to be linked to a chart account (DB trigger), and custody settlement posts its own multi-line journal via settle_custody_with_lines; this keeps every treasury movement on exact ledger accounts.
- Income statement sections are classified by account code in src/lib/incomeStatement.ts; one place to adjust the revenue/cost/station/admin/other split.
- Treasury Vouchers are the single entry point for all cash/bank receipts and payments (Treasury nav links point there); bank-to-cash cheques go through the Cash in Transit account (code 120130001) as two vouchers, so cash only increases when the cashier receives it and nothing is double-posted.
- Treasury cost-voucher suppliers come from chart posting accounts under code 221 (supplier_account_id), and flight cost reporting reads treasury_vouchers.flight_no/flight_date; new supplier accounts appear without extra setup.
- Treasury range statements and monthly flight-cost reports load all matching vouchers in ordered pages and refresh after voucher changes; this prevents API row limits and cached reports hiding financial movements.
